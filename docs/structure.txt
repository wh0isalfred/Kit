NOTE ON THE SUPPLEMENTED SECTIONS ABOVE

The raw tree export this file was generated from (29 July 2026) did not include
the batch/[batchId] subtree at all. A second, identical gap was found this
session (12 August 2026): smportal/homework/[id] was also missing from a fresh
export, for what's almost certainly the same underlying cause. Neither was
formally diagnosed, but the pattern is now consistent enough to name directly:
**this export method appears to systematically miss folders with a literal
[bracket] name** — plausibly square brackets being interpreted as a wildcard
pattern by some part of the Windows/PowerShell tooling chain used to generate
the export, even though that shouldn't affect plain recursive file enumeration.

Every file in both supplemented sections was added from build/edit history, not
from a fresh scan — each one was created, edited, and successfully deployed
during a session that produced or updated this document. Treat them as
reliable, but if you're about to do anything structural (renaming, moving,
deleting) in either the batch/[batchId] or homework/[id] trees, run a fresh
export yourself and confirm first. Don't propagate this note's confidence into
a third generation of assumed-correct documentation — verify at the source.

To regenerate a clean tree yourself:

  PowerShell (from the repo root):
    Get-ChildItem -Recurse -File -Exclude node_modules,.next,.git |
      Resolve-Path -Relative | Out-File -Encoding utf8 structure.txt

  Or, if the tree command is available:
    tree /F /A > structure.txt

If you regenerate this and EITHER [bracket] folder still doesn't show up,
that's no longer a documentation gap — that's worth actually tracking down,
since by the third occurrence it stops looking like a fluke and starts looking
like a real, reproducible limitation of whatever tool or method is producing
these exports.
